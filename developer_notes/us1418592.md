# ItemStackRequestPacket
- Converted `ItemStackRequestPacket` to CerealOnly serialization and reworked the payload binary format.
- The payload now serializes the reflected request fields directly: `Requests`, per-request `Client Request Id`, tagged action `Actions`, `Strings To Filter`, and `StringsToFilterOrigin`.
- `CraftRecipeAuto` now serializes one `Number of requested crafts` field and the `Ingredients` vector directly; the legacy duplicate craft count and separate ingredient-count byte are no longer present.
- Recipe ingredients and deprecated craft results now serialize packet-local item descriptor variants (`Empty`, `ItemName` with aux, `Molang`, and `ItemTag`) instead of the old internal item-descriptor variant bytes.
- Item stack net ID variants in slot info, mine-block actions, and craft repair/disenchant actions now serialize as a tagged cereal variant of the three concrete ID types (`ItemStackNetId`, `ItemStackRequestId`, `ItemStackLegacyRequestId`). This replaces the legacy sign-bit-tagged signed-integer encoding (positive server IDs, negative odd client request IDs, negative even legacy request IDs less than -1) and is a wire-format break.
- Cereal deserialization now rejects malformed request/action payloads, including invalid request IDs, empty action lists, out-of-range beacon effects, invalid recipe/creative/net IDs, and empty or invalid craft results.
