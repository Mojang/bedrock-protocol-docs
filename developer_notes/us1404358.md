# Network Protocol

* Converted `MovePlayerPacket` to Cereal-only serialization. The binary wire format has changed and is not backwards compatible. `NetworkProtocolVersion` is generated at CMake-configure time as `2000 + count(protocol_changelogs/*.md)`, so adding this changelog entry bumps it automatically; do not edit a hardcoded version constant.
* Player runtime ID, position, rotation, head rotation, position mode, on-ground state, riding runtime ID, teleport data, and tick now serialize as reflected fields. Teleport data is only valid with `Teleport` position mode.
* The previous wire format wrote two `int32` fields (`mCause`, `mSourceEntityType`) conditionally based on `mResetPosition == Teleport`, with **no presence byte**. The reflected representation models this as `brstd::optional<MovePlayerTeleportData>`, which Cereal always serializes with a 1-byte presence flag (`TypeSchema<brstd::optional<T>>::doSave` unconditionally calls `writeAdditionalData(has_value())`). Pointer-like bindings have the same behavior. Because no Cereal binding API can elide that discriminator while preserving the conditional payload, byte-equivalence with the legacy format is impossible — therefore this packet remains `SerializationMode::CerealOnly` rather than being downgraded to a side-by-side mode. The per-packet wire delta is +1 byte for non-`Teleport` modes and +1 byte for `Teleport` mode (presence byte before the existing 8 bytes of teleport data).
